# Generative AI Assignment 2

**Current compute route:** **Google Colab** for Phase 4 training; the laptop remains the development, artifact-verification, and final-app environment. Kaggle's GPU option was disabled for this account, and its probe ran with CPU-only PyTorch. See [Colab training setup](docs/colab_manual_setup.md) and the [Phase 4 Colab handoff](handoffs/phase_04_colab_training_handoff.md). Kaggle CLI attempt artifacts are preserved as historical evidence.

This workspace implements a small research prototype for matching patient
descriptions to individual clinical-trial criteria. It is not a clinical
decision system.

## Local setup

Use the project-local Python 3.11 environment; do not install ML packages into
the system Python:

```powershell
scripts\setup_local.cmd
```

The first setup installs CUDA-enabled PyTorch separately from the shared
package pins, then writes the exact installed local lock to
`requirements-local.lock`. Later setups restore that lock. The script also
runs the environment smoke test. Model and package caches are kept under the
project `.cache` directory on D:.

To enter the configured environment in a new PowerShell window:

```powershell
. .\scripts\activate_local.ps1
```

## Root-level setup and launcher files

These files are project support files, not temporary artifacts. Keep them
unless replacing their callers and updating this guide:

| File | Purpose and status |
|---|---|
| `requirements-base.txt` | Pinned shared Python packages. Used by local setup and included by the Kaggle requirements file. |
| `requirements-local.lock` | Exact tested Windows environment lock generated by local setup; used to reproduce that environment. |
| `requirements-kaggle.txt` | Shared package pins for the historical Kaggle CLI attempt. |
| `requirements-colab.txt` | Shared package pins for the active Colab profile; retains Colab's preinstalled PyTorch. |
| `requirements-data.txt` | Dependencies for the Phase 2 dataset preparation workflow; see `data/README.md`. |
| `Setup_Local.cmd` | Double-click wrapper around `scripts\setup_local.cmd` for initial local provisioning. |
| `Start_App.cmd` | Double-click launcher for the local Gradio screening demo in `app\main.py`. It uses the project Python environment and project model cache. |

## Local demonstration

Double-click `Start_App.cmd` or run the checked launcher
`.\.venv\Scripts\python.exe scripts\launch_app.py`. Enter a synthetic or de-identified
note, add inclusion/exclusion criteria, and inspect the exact cited source
sentences and aggregate review state. JSON and HTML downloads are explicit and
contain cited excerpts; temporary export files are cleared when the app closes.
The JSON record contains model, adapter, prompt and runtime provenance. The attention tab compares dense
and tiled implementations on synthetic tensors. The app binds to `127.0.0.1`;
The launcher checks that CUDA and the selected adapter bundle are available, and stops with a clear error instead of falling back to CPU or the base model. Base model weights must already be cached or the first load requires internet access.

See [SUBMISSION.md](SUBMISSION.md) for the current release state, model identities, evaluation artifacts, and remaining external hand-in items.

## Phase 0/1 commands

```powershell
.\.venv\Scripts\python.exe scripts\doctor.py --smoke-test --output results\environments\local.json
.\.venv\Scripts\python.exe scripts\check_tokenizers.py --output results\tokenizer_compatibility.json
.\.venv\Scripts\python.exe scripts\smoke_models.py --output results\feasibility_local.json
.\.venv\Scripts\python.exe scripts\fit_pilot.py --steps 10 --gradient-accumulation 8 --max-seq-len 1024
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Model-fit and LoRA-pilot commands use synthetic text only. For Phase 4 cloud
training, use [`notebooks/colab_runner.ipynb`](notebooks/colab_runner.ipynb)
and follow [`docs/colab_manual_setup.md`](docs/colab_manual_setup.md). It uses
Google Drive for checksummed source transfer and verified checkpoint/export
persistence. Review Drive authorization requests and never put credentials in
the notebook or repository. Verify that the current Colab session has CUDA
before running GPU-dependent cells.

`Start_App.cmd` launches the local screening app. `Setup_Local.cmd` is a
double-click wrapper for initial environment provisioning.

Build a uniquely named Colab source archive so older transfer artifacts are
preserved:

```powershell
.\.venv\Scripts\python.exe scripts\package_colab_source.py `
  --output artifacts\colab_phase04_source_20261110.zip
```

Upload the ZIP and `.sha256` sidecar to `MyDrive/GenAI_Assignment_2_source/`
as `colab_source.zip` and `colab_source.zip.sha256`, along with the current
notebook.
