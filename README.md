# Generative AI Assignment 2

**Current compute route:** Kaggle is planned for research; CLI authentication is verified, while job execution and runtime are still unverified. Earlier Colab instructions and results below are historical. Start with [Kaggle setup](docs/kaggle_setup.md). The final app remains local.

This workspace implements a small research prototype for matching patient
descriptions to individual clinical-trial criteria. It is not a clinical
decision system.

## Local setup

Use the project-local Python 3.11 environment; do not install ML packages into
the system Python:

```powershell
scripts\setup_local.cmd
```

The first setup installs CUDA-enabled PyTorch separately from the shared
package pins, then writes the exact installed local lock to
`requirements-local.lock`. Later setups restore that lock. The script also
runs the environment smoke test. Model and package caches are kept under the
project `.cache` directory on D:.

To enter the configured environment in a new PowerShell window:

```powershell
. .\scripts\activate_local.ps1
```

## Root-level setup and launcher files

These files are project support files, not temporary artifacts. Keep them
unless replacing their callers and updating this guide:

| File | Purpose and status |
|---|---|
| `requirements-base.txt` | Pinned shared Python packages. Used by local setup and included by the Colab requirements file. |
| `requirements-local.lock` | Exact tested Windows environment lock generated by local setup; used to reproduce that environment. |
| `requirements-colab.txt` | Shared package pins for Colab. Intentionally does not reinstall or override Colab's preinstalled PyTorch. |
| `requirements-data.txt` | Dependencies for the Phase 2 dataset preparation workflow; see `data/README.md`. |
| `Setup_Local.cmd` | Double-click wrapper around `scripts\setup_local.cmd` for initial local provisioning. |
| `Start_App.cmd` | Planned evaluator launcher. It is currently a Phase 10 placeholder and reports that the app is not implemented yet; replace its placeholder behavior when `app\main.py` is ready. |

## Phase 0/1 commands

```powershell
.\.venv\Scripts\python.exe scripts\doctor.py --smoke-test --output results\environments\local.json
.\.venv\Scripts\python.exe scripts\check_tokenizers.py --output results\tokenizer_compatibility.json
.\.venv\Scripts\python.exe scripts\smoke_models.py --output results\feasibility_local.json
.\.venv\Scripts\python.exe scripts\fit_pilot.py --steps 10 --gradient-accumulation 8 --max-seq-len 1024
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Model-fit and LoRA-pilot commands use synthetic text only. The Colab run is
interactive and must be authorized by the account owner. The thin notebook
runner is at `notebooks/colab_runner.ipynb`. This project was also verified
with Google's official `google-colab-cli` from Ubuntu under WSL; the CLI is
installed outside the project environment. On this Windows machine, invoke it
from an Ubuntu/WSL terminal, not PowerShell:

```bash
~/.venvs/google-colab-cli/bin/colab --auth=oauth2 sessions
~/.venvs/google-colab-cli/bin/colab --auth=oauth2 usage
```

Check account usage before allocating a GPU; its rate and availability are
not guaranteed free. Stop named sessions when finished. Do not put Google
tokens or authorization codes in the project or chat. The Phase 0/1 T4
reports and checksummed transfer evidence are preserved under `results/`.

`Start_App.cmd` is the evaluator-facing local launcher planned for Phase 10;
it reports clearly that the app is not built yet. `Setup_Local.cmd` is a
double-click wrapper for initial environment provisioning.

To prepare a source-only archive for Colab (no model weights, raw dataset,
prepared rows, or cache are included):

```powershell
.\.venv\Scripts\python.exe scripts\package_colab_source.py
```

Copy the resulting `artifacts\colab_source.zip` and
`artifacts\colab_source.zip.sha256` to `MyDrive/GenAI_Assignment_2_source/`.
Open `notebooks\colab_runner.ipynb` in Colab and run the cells in order.
